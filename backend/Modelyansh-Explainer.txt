PART 1 - WHAT THIS IS

1.1 Plain-English description

Modelyansh is a Fantasy Premier League player projection system. It starts with the official FPL player list, teams, fixtures, prices, availability flags, and recent player histories. It estimates how many goals each team is likely to score in each fixture, how likely each team is to keep a clean sheet, how likely each player is to play and start, and how a team's attacking expectation should be divided among its players. It then converts those football events into expected FPL points.

The system produces three related views:

* A deterministic rules model, called KFT in the validation files, decomposes expected points into appearance, goal, assist, clean-sheet, save, defensive-contribution, card, penalty-miss, concession, and expected-bonus components.
* A position-specific machine-learning ensemble predicts player points from historical and current features. Its final live value is composed with the calibrated probability of playing so that a conditional talent estimate becomes an unconditional expected-points estimate.
* A match-first Monte Carlo model simulates shared fixture outcomes, discrete player-minute states, scorers, assisters, defensive events, cards, and proxy bonus. It produces distributions such as floor, upside, return probability, haul probability, and score brackets.

The primary audience is an FPL analyst who wants auditable player-week projections rather than a single opaque rank. The raw files expose intermediate quantities such as fixture lambda, expected minutes, xG, xA, scoring components, model source, and simulation probabilities. The legacy exporter serves a pre-existing website or notebook contract with fixed CSV names.

The system is not an optimizer for transfers, captains, chips, budgets, or squads. It does not ingest live injury news automatically. It does not reproduce the official Bonus Points System exactly. It does not contain a neural network. It is a projection engine and validation framework.

1.2 Technical framing

At a high level the repository implements:

    official and external data
        -> normalized teams, players, fixtures, histories, odds, and priors
        -> team fixture goal intensities and clean-sheet probabilities
        -> player rates and four-output minutes probabilities
        -> deterministic expected FPL scoring
        -> optional XGBoost plus Random Forest player-points ensemble
        -> match-first Monte Carlo distributions
        -> raw tables, snapshots, validation reports, and legacy website CSVs

The live entry point is `fpl_xpts.cli:main`, which constructs `AppConfig` and calls `pipeline.run_live_projection`. The replay entry point is `scripts/retrospective_replay.py`, which reconstructs each historical gameweek using only shifted or pre-deadline information, applies season-specific scoring boundaries, and evaluates deterministic, ML, and Monte Carlo outputs against actual points.

The installed package name and console command are `fpl-xpts`; the repository and this explainer call the overall system Modelyansh. [CURRENT REPOSITORY AUDIT, `pyproject.toml`]

`src/fpl_xpts/features.py`
Role: builds player rates, priors, form, set-piece, penalty, assist, and Understat-enhanced features.
Key decisions:
* Observed per-90 rates are shrunk toward priors with 900 prior minutes.
* Established players use Premier League positional evidence when at least 450 relevant minutes are available.
* Foreign signings use their latest recognized league season, provisional league-strength factors, and another 900-minute shrink toward the latest Premier League positional median before current Premier League evidence is blended.
* Provisional foreign factors are La Liga 0.9625, Bundesliga 0.9769, Serie A 0.9741, and Ligue 1 0.9352. They come from a Glicko-derived audit and are not proven causal transfer coefficients.
* Recent form uses up to 10 matches with a four-match half-life, but the live blend weight is currently 0.0, so form is calculated for audit and has no default projection effect.
* Understat evidence can receive up to 65 percent weight by 900 minutes.
* Penalty event probabilities are represented as score 0.78, saved 0.17, missed wide/post 0.05.
* The default team assist factor is empirically shrunk and clipped to 0.62-0.82 around the config value 0.73.
* Per-90 xG caps are GK 0.01, DEF 0.18, MID 0.58, FWD 1.00; xA caps are GK 0.02, DEF 0.22, MID 0.70, FWD 0.45.
Inputs: FPL players and histories, Understat player/shot profiles, optional set-piece and foreign-league data.
Outputs: player profile/rate columns consumed by projections, xPts, ML features, and MC.

`src/fpl_xpts/forecast.py`
Role: team fixture goal and clean-sheet forecast.
Key functions: `build_team_strength`, `forecast_fixture_lambdas`, `add_team_scoring_probabilities`.
Baseline logic: starts from league goal average 1.51 and home advantage 1.10, combines normalized FPL team attack and opponent defence, and clips fixture lambdas to 0.15-4.00. Poisson clean-sheet probability is `exp(-opponent_lambda)`.
Override logic: if an Elevenify file is discoverable, its projected goals replace the baseline lambdas and its direct clean-sheet probabilities are retained alongside Poisson trace values. Named scoring probabilities include P(0), P(1), P(2), P(2+), and P(3+).
Critical caveat: the function searches for the root Elevenify sheet itself. Consequently, `--no-elevenify` does not guarantee that Elevenify is absent while the root sheet remains discoverable.

`src/fpl_xpts/projections.py`
Role: parsers and override application for Elevenify and optional external team projections.
Key functions: team-name normalization, `load_elevenify_projection_tables`, `find_elevenify_projection_file`, `apply_elevenify_team_projections`, and external-file loaders.
Logic: parses the two Elevenify sections into explicit `elevenify_goals` and `elevenify_cs` DataFrames indexed by normalized team and gameweek; applies direct goals and direct clean-sheet values rather than proportional rescaling.
Caveat: current direct assignment treats a team-gameweek value as each fixture value. A double gameweek can therefore duplicate a weekly team projection rather than split it, despite an older docstring implying a split.

`src/fpl_xpts/market_odds.py`
Role: retrieves bookmaker markets and solves fixture goal intensities.
Key functions: Odds API retrieval, team matching, devigging, Poisson market probabilities, and lambda fitting.
Logic: requests `soccer_epl` head-to-head and totals markets from The Odds API; takes median bookmaker prices; converts inverse odds to probabilities and normalizes the overround away; grid-searches home and away lambdas from 0.10 to 4.50 in 0.05 steps. The objective weights 1X2 error by 3, over/under error by 2, and a fallback total-goals anchor by 0.35.
Environment: reads `ODDS_API_KEY`.
Caveat: this is an independent-Poisson market inversion, not Dixon-Coles. If the API key, market, team match, or event is unavailable, the baseline/Elevenify layer remains.

`src/fpl_xpts/shot_profiles.py`
Role: Understat acquisition and matching.
Key functions: load/fetch team and player stats, match shots, build shot profiles, fetch foreign leagues.
Logic: matches normalized full player name plus team first, then uses web name as a fallback. A big-chance proxy classifies a shot as large when xG is at least 0.30.
Live scope: EPL profiles are integrated automatically. Foreign-league collection exists as a utility and cached-data path rather than a guaranteed live fetch on every run.

`src/fpl_xpts/minutes.py`
Role: heuristic minutes fallback and discrete-minute-state construction.
Key functions: `estimate_start_and_minutes`, `minute_outcomes`, trained-model wrapper.
Heuristic logic: appearances are historical rows with minutes above zero; starts use the FPL `starts` field or infer at least 60 minutes; average minutes per appearance is multiplied by `0.85 + 0.15 * start_rate` and then by availability. When a play probability is supplied, likely minutes mean minutes conditional on appearing.
Discrete output: no appearance, sub appearance, start below 60, and start at least 60 states with probabilities and representative minutes.
Use: deterministic xPts consumes expected minutes; Monte Carlo samples the discrete states.

`src/fpl_xpts/minutes_model.py`
Role: calibrated four-output trained minutes model.
Outputs: `p_play`, `p_start_given_play`, `mins_if_start`, and `mins_if_sub`.
Features: 47 columns containing shifted 1-, 3-, 5-, 6-, and 10-gameweek usage, availability/missingness, recency, fixture context, congestion, transfer episodes, standings, and season-phase/stakes interactions.
Models: classifier outputs average XGBoost and Random Forest probabilities and apply team-disjoint out-of-fold isotonic calibration; regression outputs average XGBoost and Random Forest predictions.
Composition: expected minutes are `p_play * (p_start_given_play * mins_if_start + (1-p_start_given_play) * mins_if_sub)`.
Fallback: live and replay retain the rolling-history heuristic if the trained model or required features are unavailable.

`src/fpl_xpts/minute_overrides.py`
Role: schema validation, player matching, template creation, and application of manual minute inputs.
Reads/writes: reads configured minutes CSVs; can write a template; returns match diagnostics and updated player/fixture rows.
Decision: manual information is applied after trained estimates because injury, manager-news, suspension, and tactical knowledge are not fully represented in historical features.

`src/fpl_xpts/scoring.py`
Role: compact current live scoring helpers.
Rules encoded: goal points GK 10, DEF 6, MID 5, FWD 4; clean-sheet and defensive-contribution thresholds, with DEF threshold 10 and MID/FWD threshold 12.
Caveat: these are current live-oriented helpers, not intrinsically season-aware. Historical replay wraps their imported bindings with a season scoring context.

`src/fpl_xpts/bonus.py`
Role: deterministic expected-bonus approximation.
Logic: maps expected attacking and defensive events to a capped expected bonus proxy.
Caveat: it is not the official BPS algorithm and should not be described as one.

`src/fpl_xpts/xpts.py`
Role: deterministic player-fixture and player-week expected-points engine.
Allocation:
* Team xG and xA are conserved across players using each player's rate multiplied by expected-minute share.
* Fixture minute capacity is capped at 90 goalkeeper minutes and 900 outfield minutes per team, with priority rules deciding who is reduced.
* `P1_GA = 1 - exp(-(xG+xA))` is a Poisson at-least-one goal-or-assist approximation.
Scoring components: appearance, goals, assists, clean sheets conditional on reaching 60 minutes, goalkeeper saves, defensive contributions, cards, conceded-goal penalties, penalty misses, and expected bonus.
Aggregation: fixture rows become player-gameweek rows; weekly expected-point components are summed.
Caveats: bonus is heuristic; own goals, penalty saves, exact BPS ties, and exact red-card concession timing are not fully represented.

`src/fpl_xpts/ml_features.py`
Role: creates the 103-column points-model feature schema.
Logic: joins player, team, fixture, rate, price, form, role, minutes, and historical context; enforces stable feature ordering; fills downstream missing values through the model preprocessing contract.
Use: both training and live/replay inference. A separate validation experiment added play-probability features to make 104 columns, but those bundles were not shipped.

`src/fpl_xpts/ml_models.py`
Role: position-specific points ensemble training, loading, validation, and prediction.
Model design: one bundle for each of GK, DEF, MID, and FWD. Each bundle combines an XGBoost regressor with 350 trees, maximum depth 4, and learning rate 0.035, plus a Random Forest with 250 trees, maximum depth 12, and minimum leaf size 15. The ensemble is the simple average.
Validation: team-disjoint grouped folds reduce leakage from teammates and shared fixtures.
Live output: `ml_xpts_pre_minutes` retains the raw conditional model estimate; final `ml_xpts` composes it with calibrated play probability.

`src/fpl_xpts/monte_carlo.py`
Role: match-first simulation and distribution summaries.
Key functions: minute draws, fixture simulation, bonus allocation, and `simulate_player_week`.
Logic: groups all players in one fixture, draws shared home and away goals from Poisson lambdas, samples each player's discrete minute state, allocates scorers and assisters with normalized shares, draws saves, defensive contributions, cards, penalty misses, and proxy BPS, then applies FPL scoring. Shared fixture draws make opposing clean sheets and team goals internally coherent.
Outputs: mean, standard deviation, floor, quartiles, upside, min/max, attacking-return counts, return and haul probabilities, and point brackets.
Definitions: `P_return` means at least 6 FPL points; `P_haul` means at least 10 FPL points; `MC_P1_Return` means at least one simulated goal or assist, not six points.
Caveat: fixed BPS-like weights are a simulation proxy, not official BPS.

`src/fpl_xpts/historical_validation.py`
Role: constructs historical training and replay-ready data.
Coverage: football-data odds from 2014-15 through 2025-26; Vaastav player-gameweek data from 2016-17 through 2025-26; Understat historical data from 2014 onward where cached.
Logic: prefers closing odds where available; normalizes team/player identities; creates shifted rolling features so the current gameweek cannot see its own outcome; uses direct Understat historical xG where older Vaastav rows lack xG; replaces the partial 2025-26 Vaastav cache with official cached FPL history only after completeness checks through GW38.
Caveats: historical schemas vary, old season gameweek numbers can exceed 38 because of restart naming, and availability coverage is sparse.

`src/fpl_xpts/backtest.py`
Role: older standalone backtest and simple ridge/logistic approximation.
Status: legacy/provisional. It does not reproduce the current deterministic, four-output minutes, position-ensemble, and match-first replay stack. Use `scripts/retrospective_replay.py` for authoritative current validation.

`src/fpl_xpts/legacy_export.py`
Role: converts raw pipeline tables into the fixed website/notebook file contract.
Outputs: weekly, fixture, six-week, top-50, QC, form-audit, and Monte Carlo bracket CSVs.

`src/fpl_xpts/pipeline.py`
Role: live orchestration.
Actual order:
1. Fetch official bootstrap, fixtures, player summaries, and event data.
2. Build team and player features, including Understat profiles.
3. Construct baseline fixture lambdas. This function can already auto-apply Elevenify.
4. Apply market-odds lambdas when available.
5. Apply the explicit Elevenify override again when enabled.
6. Apply optional external team files last when enabled.
7. Estimate minutes with the trained model or heuristic.
8. Apply configured manual minutes.
9. Apply the hard-coded `player_minutes_inputs_gw37_to_38.csv` if it exists.
10. Apply compact minute overrides.
11. Build deterministic fixture/week xPts.
12. Optionally run Monte Carlo from the deterministic player-fixture rates and attach its tail probabilities.
13. Optionally infer and attach position ML xPts to the weekly table.
14. Always write a timestamped JSON snapshot and requested CSV outputs.
This order, including the duplicate Elevenify opportunity and hard-coded minutes file, is the code's current behavior.

PART 5 - MODELLING DECISIONS AND WHY

5.1 Market odds rather than a home-grown Dixon-Coles live model

Problem: team scoring expectation must react to current strength, injuries, venue, and matchup. A historical score model needs careful decay, promotion handling, and parameter calibration.

Choice: when current bookmaker markets are available, invert devigged 1X2 and totals consensus into independent-Poisson home/away lambdas. The market aggregates more information than the repository's FPL-strength baseline.

Why not claim Dixon-Coles: the code does not estimate Dixon-Coles low-score correlation. FiveStat uses a multiplicative Dixon-Coles and bivariate-Poisson approach, but Modelyansh does not. [CURRENT EXTERNAL FACT, `https://www.fivestat.co.uk/methodology`, checked 2026-06-13]

Evidence and limitation: market odds are a principled source and improve historical context, but the repository does not contain a clean odds-versus-no-odds ablation proving a universal gain. Moreover, current override order often lets Elevenify replace market lambdas. The correct claim is that odds solve an information problem, not that this exact implementation has isolated causal superiority.

5.2 Match-first rather than independent player Monte Carlo

Problem: independently simulating every player can create impossible joint states, such as both opposing teams keeping a clean sheet, player goals that do not sum to team goals, or assist/scorer combinations detached from the match.

Choice: draw one result per fixture, then allocate events among participating players. Clean sheets, conceded goals, scorer shares, and opponent outcomes are shared.

Evidence: internal coherence follows directly from construction. Completed 2025-26 replay does not show lower point MAE than deterministic rules: baseline MC MAE 1.819519 versus rules 1.815170, with per-GW Spearman 0.490025 versus 0.495986. [COMPLETED-SEASON VALIDATION, `outputs/validation/retrospective_minutes_final_2025_26/metrics_by_position.csv`] Its value is distributional coherence and probabilities, not a demonstrated mean-point accuracy win.

5.3 Discrete minute outcomes rather than a continuous minute draw

Problem: FPL scoring changes discontinuously at appearance and 60-minute thresholds. A smooth normal distribution around expected minutes misrepresents no-shows, substitute cameos, starts below 60, and full starts.

Choice: model no appearance, substitute appearance, start below 60, and start at least 60. This preserves the appearance and clean-sheet thresholds and can represent a player with high minutes conditional on playing but material no-show risk.

Evidence: the final play-probability composition reduced zero-minute-row MAE from 1.397793 to 0.891091 and reduced the share of zero-minute rows projected above 2 points from 22.6051 percent to 10.4964 percent, without reducing nonzero Spearman. [COMPLETED-SEASON VALIDATION, 2025-26 unseen minutes holdout/replay, `outputs/validation/minutes_model_findings.md`]

5.4 XGBoost plus Random Forest rather than a neural network

Problem: the points dataset is medium-sized, tabular, heterogeneous, missing-valued, nonlinear, and split by position. It does not have the volume or sequence/image structure that makes a neural network an obvious first choice.

Choice: XGBoost handles nonlinear interactions and sparse/missing tabular structure; Random Forest provides a differently biased tree ensemble; averaging reduces dependence on one learner. Position-specific models avoid forcing one response surface across goalkeepers, defenders, midfielders, and forwards.

Evidence: on the stored unseen 2024-25 holdout, the ensemble improved pooled Spearman from deterministic 0.340529 to 0.512374 and MAE from 1.940812 to 1.740577. [COMPLETED-SEASON VALIDATION, `outputs/validation/ml_model_comparison.csv`] The improvement is evidence for this ensemble over the current rules baseline, not proof that no neural network could do better.

5.5 Four-output minutes model

Problem: directly regressing expected minutes conflates four different questions: will the player appear, will he start if he appears, how long will he play when starting, and how long will his substitute cameo last.

Choice: estimate those four conditional quantities separately, calibrate the two probabilities, then compose them. This makes manual adjustment and debugging possible.

Evidence: full unseen 2025-26 holdout play-probability Brier score is 0.086821 and minutes MAE is 12.850099. On the complete-feature replay slice, Brier is worse at 0.131981. [COMPLETED-SEASON VALIDATION, `models/minutes_model.pkl` metadata and `outputs/validation/minutes_model_findings.md`] The model passes the defined zero-minute gates but remains weak for unexpected absences among recent regulars.

5.6 Compose `ml_xpts` with play probability

Problem: the points ranker learns most clearly from players who play and can over-project a talented player who is absent. Adding play probability as one more feature did not force the prediction to become an unconditional expectation.

Choice: retain raw `ml_xpts_pre_minutes`, then scale/compose it with calibrated `pred_play_prob` in the production path. Keep the direct 104-feature stacking experiment out of production.

Evidence: direct stacking reduced zero-minute MAE only to 1.236697, left 19.0009 percent of zero rows above 2 points, and reduced nonzero Spearman from 0.344326 to 0.341557. Final composition reached 0.891091 zero-minute MAE, 10.4964 percent above 2, and 0.345617 nonzero Spearman. [COMPLETED-SEASON VALIDATION, `outputs/validation/minutes_model_findings.md`]

5.7 Heavy shrinkage for new players

Problem: a player's first few hundred minutes can generate extreme per-90 values, while direct foreign-league translation ignores competition and team context.

Choice: require meaningful evidence, use 900 prior minutes in both foreign-to-EPL shrinkage and current-EPL updating, cap position rates, and fall back toward Premier League positional medians.

Evidence: tests verify mathematical behavior and prevent unshrunk small samples. The repository does not yet contain a clean new-signing-only holdout proving the 900-minute value is optimal. The factors and prior weight are defensible stabilizers but remain PROVISIONAL calibration choices.


PART 6 - VALIDATION AND ACCURACY

6.1 What is being measured

Actual target: official FPL points for a player in a gameweek.

MAE: mean absolute error between predicted and actual points. Lower is better. It measures numeric closeness but rewards conservative predictions because FPL scores are noisy and right-skewed.

RMSE: root mean squared error. Lower is better. It penalizes large misses more heavily than MAE.

Spearman correlation: rank correlation within the evaluated rows or gameweek. Higher is better. It measures whether the model orders players correctly, which is often more useful for selection than exact point error.

Per-GW mean and standard deviation: the replay calculates a metric within each gameweek, then reports the mean and sample standard deviation across gameweeks. This prevents large gameweeks from silently dominating and exposes week-to-week volatility.

`>2` subset: rows whose actual points exceed 2. It focuses on players who did more than appearance-only scoring. This is not the same as a haul.

`P_return`: Monte Carlo probability that total FPL points are at least 6.

`P_haul`: Monte Carlo probability that total FPL points are at least 10.

Top-20 hit count: among the 20 players with the highest predicted `P_haul` in a gameweek, how many actually scored at least 10.

Calibration gap: predicted probability or percentile statistic minus observed result inside a bucket; the reports summarize mean absolute gap across buckets. Probability gaps are in probability units; floor/upside gaps are in points, so they must not be compared on one common scale.

6.2 Replay methodology

The authoritative replay is `scripts/retrospective_replay.py`.

For each selected season and gameweek it:

1. Restricts inputs to rows available before that gameweek through shifted historical fields.
2. Builds team fixture expectations from historical odds and available team context.
3. Builds deterministic player features and minutes without using the target game's result.
4. Applies the scoring rules for that historical season.
5. Runs deterministic KFT, the stored position ML ensemble, baseline MC, and ML-weighted MC.
6. Joins actual FPL points/minutes only after prediction.
7. Writes row-level predictions, per-GW/per-position metrics, calibration buckets, and a findings report.

GW1 is normally absent because shifted in-season features do not yet exist, so a conventional season replay contains 37 evaluated gameweeks. A model bundle's training cutoff still matters: a replay season that overlaps its training data is descriptive, not a clean unseen holdout.

6.10 Honest accuracy summary

Strongest evidence:

* The position ML ensemble consistently improves full-sample ranking over deterministic rules on unseen 2024-25 and 2025-26.

PART 7 - BIG QUESTIONS

7.1 Is this a neural network?

No. The points model is an average of XGBoost and Random Forest regressors, trained separately by position. The minutes model uses XGBoost and Random Forest classifiers/regressors plus isotonic calibration. The deterministic and Monte Carlo layers are rules/probability code. No neural-network library, architecture, embedding, or learned deep sequence model is present.

7.2 What makes a prediction correct or incorrect?

A point prediction is numerically better when its absolute error is smaller. A ranking is better when players are ordered more like actual results, measured here by Spearman. A probability is better when observed frequencies match predicted frequencies, measured through Brier score and calibration buckets.

One player scoring 15 after a 4-point projection does not by itself prove the model was irrational. A 15-point outcome may be rare but plausible. The model is wrong in a useful engineering sense when repeated comparable cases are biased, misranked, or miscalibrated. Examples in this repository are zero-minute recent regulars, high-haul bonus, and ML-weighted upside.

7.3 Why cannot deterministic xPts exceed about 7?

It can. There is no hard 7-point cap.

The saved completed 2025-26 GW38 legacy file has a maximum deterministic value of 7.153601 for Erling Haaland. [STALE 2025-26 OUTPUT, `outputs/legacy_live/weekly_player_week.csv`]

The final 2025-26 replay has a deterministic maximum of 13.023829 for Haaland in GW36, where actual points were 11. [COMPLETED-SEASON VALIDATION, `outputs/validation/retrospective_minutes_final_2025_26/retrospective_replay_predictions.csv`]

The same replay has an ML maximum of 11.756929 for Marc Guehi in GW36, where actual points were 15. [same source/status]

Single-fixture expected values often cluster below 7 because an expectation averages many score outcomes. A forward with a 40 percent chance of scoring does not receive full goal points; he receives 0.4 times the goal value before other components. Double gameweeks, extreme lambdas, near-certain minutes, penalty duty, and strong clean-sheet/bonus expectation can raise the mean well above 7.

7.4 How are new and promoted players predicted?

New player already in the Premier League: use prior EPL per-90 evidence when sufficient, shrink it toward the position prior, then update with current-season minutes.

Foreign signing from a recognized league: use the latest foreign season, apply a provisional league factor, shrink heavily toward the EPL positional median, then update as EPL evidence arrives.

Player with no matched history: use position/team/role defaults and manual minutes until evidence accumulates.

Promoted player with Championship history: the current code has no full Championship event-rate integration comparable to Understat's recognized foreign leagues. It therefore leans on generic positional/team priors, FPL price/role, team projection, and manual minutes. This is a genuine capability gap.

Promoted team: the team fixture layer can use market odds or Elevenify once available, which is safer than pretending the previous EPL strength field exists. Before markets/external projections exist, a manually set conservative attack/defence prior is required. The repository does not yet expose a polished promoted-team prior configuration file, so this step is operational/manual.

7.5 Why does accuracy drift on unseen seasons, and what fixes it?

Sources of drift:

* Scoring rules change, such as goalkeeper goal points, BPS, or defensive contributions.
* New teams and players lack the same history distribution.
* Team managers, tactics, roles, transfers, and penalty takers change.
* Availability data quality changes.
* FPL/Understat/Vaastav schemas and update timing change.
* Model training optimizes older patterns.
* Manual files or fixture projections remain stale.

Fixes:

* Make season rules explicit and test boundaries.
* Save pre-deadline snapshots every gameweek.
* Retrain only after rolling-origin gates pass on unseen seasons.
* Recalibrate play and MC probabilities.
* Add better injury/news availability.
* Build Championship/promoted-team priors.
* Keep source and feature failure reports.
* Compare old and new models on identical rows before replacement.

The retraining experiment shows why blind annual retraining is not enough: new rows slightly improved MAE but weakened ranking in both the new and older checks.

7.6 Rules-based versus ML: why keep both?

Rules-based strengths:

* Every point can be decomposed into football/scoring causes.
* It works for players with sparse labels if team, role, rates, and minutes are supplied.
* It provides stable inputs for Monte Carlo.
* It exposes whether a miss came from minutes, lambda, event share, or scoring.

ML strengths:

* It learns nonlinear interactions and systematic residuals omitted by the rules.
* It materially improves overall ranking and MAE on unseen holdouts.

Keeping both enables triangulation. When ML and deterministic xPts disagree, the difference is itself an audit signal. Removing the rules model would sacrifice explanation and new-player fallback; removing ML would discard demonstrated ranking gains.

7.7 How does Modelyansh differ from Solio, FPL Review, OpenFPL, and FiveStat?

Solio:
Publicly accessible here through a latest JSON API. Modelyansh can normalize that feed for current descriptive comparison. It cannot reproduce historical same-deadline Solio predictions without an archive, so no fair accuracy claim is made.

FPL Review:
Its public Massive Data Model description indicates a sophisticated proprietary projection process. Modelyansh is local, inspectable, and exposes source code, intermediate tables, replay rows, and every scoring component. That transparency is a capability difference, not proof of better forecasts.

OpenFPL:
OpenFPL is a published public ensemble using FPL and Understat data with a prospective 2024-25 evaluation. Modelyansh adds an explicit match-first simulator, direct Elevenify/odds fixture overrides, a four-output calibrated minutes model, foreign-signing priors, manual minutes workflow, season-aware replay metadata, and a legacy website contract. OpenFPL's paper has cleaner published benchmark context; Modelyansh should not claim superiority without an identical evaluation slice.

FiveStat:
FiveStat publicly documents team attack/defence, recency, Dixon-Coles/bivariate-Poisson score modelling, and player share allocation. Modelyansh currently uses independent-Poisson lambdas, often supplied by markets/Elevenify, and then a richer player-event simulation. FiveStat is a methodology reference, not a code or data dependency.

What Modelyansh can do that the compared public surfaces do not all expose:

* Run entirely in the user's local repository.
* Show deterministic point-component decomposition.
* Swap or audit fixture-lambda sources.
* Apply explicit player minutes overrides.
* Produce shared-match Monte Carlo distributions.
* Replay historical gameweeks with row-level season-rule metadata.
* Export an existing website's fixed CSV contract.

These are verified local capabilities, not a statement that competitors lack internal equivalents.

9.3 Promoted-team priors

Current gap: there is no dedicated promoted-team prior module.

Practical first-season method:

1. Create an explicit config table for each promoted team with attacking strength, defensive strength, home adjustment, and evidence source.
2. Prefer current bookmaker season/match markets and a new Elevenify sheet once available.
3. Before markets exist, regress Championship performance strongly toward a newly promoted EPL baseline rather than translating it one-for-one.
4. Keep the prior separate from observed EPL updates.
5. Increase EPL evidence weight gradually as matches accumulate.
6. Report the prior source in every fixture row.

Do not infer a precise prior from this repository's current code; that capability is not implemented.

9.4 New-signing priors

For recognized foreign-league players:

* Confirm identity, position, prior team, season, minutes, and role.
* Use the latest cached foreign season.
* Apply the existing provisional league factor.
* Retain 900-minute shrinkage unless a new-signing cohort validation justifies changing it.
* Manually set expected minutes and likely role.

For Championship, Eredivisie, Portugal, non-Understat, academy, or long-inactive players:

* Use a position/team prior.
* Add manual role, set-piece, penalty, and minutes information.
* Flag the row as weak/provisional.
* Avoid presenting player-specific precision unsupported by source data.

9.6 Every-gameweek workflow

Immediately after the previous deadline:

* Save actual points/minutes/event-live data for the closed gameweek.
* Do not overwrite the pre-deadline prediction snapshot.
* Join predictions to actuals and calculate MAE, Spearman, zero-minute errors, top-20 `P_haul` hits, and calibration buckets.

Early week:

* Refresh fixtures, postponements, player/team data, and external source availability.
* Update rolling features only with completed matches.
* Review transfers, suspensions, new managers, and role changes.

Before deadline:

* Update the manual minutes file.
* Refresh odds and Elevenify.
* Run the raw pipeline.
* Save a timestamped prediction snapshot.
* Save a separate availability snapshot before the deadline.
* Review top discrepancies between deterministic and ML.
* Review top-20 `P_haul`, high-upside, and low-play-probability players.
* Export and publish the legacy/site files only after freshness checks.

After matches:

* Store actual outcomes separately.
* Append gameweek validation without changing the old prediction.
* Diagnose misses by minutes, team lambda, player share, scoring event, bonus, or calibration.
* Retrain only on a scheduled cadence and only with gate comparisons.

9.7 Why snapshots matter

Without a pre-deadline snapshot, later API values can contain the result, updated minutes, final availability, or corrected fixtures. A model can then appear more accurate through hindsight leakage.

Snapshots provide:

* The exact player/fixture universe seen by the model.
* The availability state known before deadline.
* The exact odds/Elevenify/manual inputs used.
* Reproducible feature values and model versions.
* Fair weekly calibration and hit-rate tracking.
* Evidence that a cached completed-season file was not presented as live.

Use immutable directory names containing season, GW, UTC timestamp, and model/config version.

FINAL OPERATING POSITION

Modelyansh is a working, tested, auditable FPL projection stack with deterministic, machine-learning, minutes, and match-first simulation layers. Its strongest verified value is transparent decomposition plus improved unseen-season ranking from the position ensemble and a materially better treatment of no-show risk from the four-output minutes model.

It is not currently ready to publish a live 2026-27 forecast because the official new-season player universe is not yet present and the checkout still contains auto-discoverable completed-season inputs and stale GW defaults. The next live result becomes valid only after those inputs are replaced, new scoring rules are confirmed, promoted/new-player priors are set, manual minutes are refreshed, and a timestamped pre-deadline snapshot is saved.

No cached GW38 row in this repository is a live prediction.
